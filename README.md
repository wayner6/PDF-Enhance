# PDF-Enhance · PDF 增强

**正式版：1.1.0** · [Windows 下载](https://github.com/wayner6/PDF-Enhance/releases/tag/v1.1.0) · [AGPL-3.0-only](LICENSE)

本分支为 **1.2.0rc1 测试版**，新增 PDF 压缩和密码去除，不创建 Release，不替换正式版。测试包仅通过 GitHub Actions 提供。

让扫描 PDF 可以搜索、复制，并通过书签快速跳转到章节。

PDF-Enhance 面向扫描文档、电子书、技术规范和长篇资料，提供本地 OCR、可搜索文字层、目录解析与书签生成。Windows 桌面版支持自动处理；命令行向导支持目录校对和可选视觉 AI。

默认使用本地 OCR，不需要 AI API Key。启用视觉 AI 后，所选目录页的图片会发送到配置的外部服务。

## 核心能力

- **生成可搜索 PDF**：保留扫描底图和版式，添加不可见文字层，支持搜索、复制和划词；按 OCR 字符坐标对齐文字层。
- **从目录生成书签**：解析章节标题、页码和层级，推算目录页码与 PDF 实际页序的偏移，并尽量定位到章节标题位置。
- **按需识别**：仅制作书签时不生成全文文字层；桌面版优先读取正常文字层，必要时才执行 OCR，并在同一任务内复用识别结果。
- **人工校对**：命令行可导出目录文本，修改标题、页码和层级后重新加载，也可手动指定目录页和页码偏移。

> OCR 和目录解析不保证所有文档都能正确识别。重要资料处理后，请抽查搜索结果、复制文字及书签跳转位置。

## 快速开始

### Windows 桌面版

从 [v1.1.0 Release](https://github.com/wayner6/PDF-Enhance/releases/tag/v1.1.0) 下载 Windows x64 发行包，无需安装 Python：

- **单文件版**：直接运行 `PDF-Enhance.exe`，首次启动可能较慢。
- **便携版**：解压 `PDF-Enhance-Windows.zip`，运行其中的 `PDF-Enhance/PDF-Enhance.exe`。请保留旁边的 `_internal` 文件夹，不要只复制 exe。

正式版通过 Release 提供下载；开发构建仍可在 [GitHub Actions](https://github.com/wayner6/PDF-Enhance/actions/workflows/windows-build.yml) 成功运行的 **Artifacts** 中查找，下载通常需要登录 GitHub。工作流不会自动发布 Release。

1. 选择输入 PDF 和输出目录。
2. 按目标选择任务，设置 OCR 并发进程数。
3. 点击“开始处理”，等待完成提示；需要停止时点击“中断处理”。
4. 打开输出 PDF：尝试搜索正文文字、复制一段文字，或点击书签检查跳转。

假设输入文件为 `文档.pdf`：

| 任务 | 适用需求 | 成功时输出 |
| --- | --- | --- |
| 仅全文 OCR | 只需要搜索、复制，不需要目录 | `文档_ocr.pdf` |
| 全文 OCR + 制作书签 | 同时需要可搜索文字层和章节导航 | `文档_ocr_bookmark.pdf` |
| 仅制作书签 | 已有可用文字层，或只需要章节导航 | `文档_bookmark.pdf` |

**全文 OCR 会重新识别全部页面。** 对有全页扫描底图的页面，会清除旧 PDF 文字层，其中的文字水印也可能被清除；印在扫描图片里的水印不受影响。只需要导航时，选择“仅制作书签”。

组合任务成功时只导出 `_ocr_bookmark.pdf`；若全文 OCR 已完成但目录或书签生成失败，会提供保存 `_ocr.pdf` 的流程，已有同名文件需确认后才覆盖。

中断会终止全文 OCR 的进程池，并停止后续解析、定位和保存；正在执行的单页本地 OCR 或 PDF 保存调用需等待当前调用结束后清理。中断发生在最终保存前时，不导出本次结果，也不覆盖已有输出；保存已完成时会如实提示已完成。清理结束后可以开始新任务。

桌面版自动识别目录页和页码偏移，不提供人工校对或视觉 AI。自动处理失败时，可使用下方命令行向导。启动时窗口尺寸即为最小尺寸，基准 **520×350**，按 DPI 和控件所需尺寸调整，仍可手动放大。

### 从源码运行

要求 **Python 3.10+**。命令行可用于 Windows、Linux 和 macOS；Windows 打包脚本使用 Python 3.12。OCR 使用 CPU，目前未启用 NVIDIA GPU 推理。

先克隆仓库并进入项目目录：

```bash
git clone https://github.com/wayner6/PDF-Enhance.git
cd PDF-Enhance
```

建议使用虚拟环境。按系统选择一组命令：

**Windows PowerShell：**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe pdf_enhance_gui.py
```

**Linux / macOS（命令行）：**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python pdf_enhance.py "/path/to/document.pdf"
```

将示例路径替换为实际 PDF 路径；不传路径则由向导询问。安装依赖需要联网。本地 OCR 处理不需要启用视觉 AI。

以下命令均在项目目录中执行，`python` 指已安装项目依赖的 Python 解释器；使用上述虚拟环境时，可替换为对应的解释器路径。

## 源码新增：PDF 压缩与密码去除

以下两项已接入开发源码，**尚未包含在 v1.1.0 正式发行包中**。任务改为下拉选择，按任务显示对应设置，保留开始、中断和最小尺寸窗口。

- **PDF 压缩**：默认无损结构优化，另存 `_compressed.pdf`。可选均衡、强力两个有损图片压缩档位；不重新 OCR、不将整页转为图片，保持文字、书签等 PDF 结构。原有加密不自动去除；需要打开密码时在遮蔽输入框填写。有损结果不比无损结果更小时采用无损结果；最佳结果仍没有体积收益时输出原始字节副本并明确提示，不保留无收益的有损结果。
- **PDF 密码去除**：输入已知用户或所有者密码，另存 `_unlocked.pdf`；仅有权限限制、用户密码为空的文档也可处理。只处理有权修改的文件，不猜测或破解密码。密码不写入配置或日志，提交任务后界面清空密码框。

带签名字段的文档暂不处理。最终保存前可中断；图片重写和保存是原生调用，可能需要等待当前调用结束再清理。第三方方案比较、所用 API、压缩参数及安全保存逻辑见 [调研与实现说明](docs/pdf-tools-research.md)。

## 命令行向导与目录校对

```bash
python pdf_enhance.py "你的文档.pdf"
```

命令行仍是**交互式向导**，传入文件路径不代表无人值守处理。安装项目后，也可使用 `pdf-enhance "你的文档.pdf"`；支持 `--help` 和 `--version`。

### 处理流程

1. **检查文字层**：根据文档情况，选择全书 OCR、仅补全缺少文字层的页面，或不生成全文文字层的轻量书签模式。
2. **指定目录页**：输入 PDF 实际页序，例如 `5-8` 或 `5,6,7`；直接回车尝试自动查找。
3. **解析并预览**：读取目录，计算页码偏移，显示书签层级和目标页。
4. **校对或生成**：可直接写入书签，也可导出目录文本、修改偏移或重新选择目录页。

“仅补全”只在向导提供该选项时可用，不是修复已有乱码文字层的模式。已经过 PDF-Enhance OCR 处理且被识别为已处理的文件，向导会跳过 OCR；桌面版全文 OCR 任务仍会重新识别全部页面。

### 页码偏移是什么？

目录中的逻辑页码与阅读器显示的 PDF 实际页序可能不同：

```text
目标 PDF 页序 = 目录逻辑页码 + 偏移
```

例如，目录写“第 1 页”，但正文实际从 PDF 的第 8 页开始，则偏移为 `+7`。节选文档也可能需要负偏移。

### 校对目录文本

在向导中选择“导出 toc.txt 后校对”，编辑导出的 UTF-8 文件，保存后回到终端按回车重新加载：

```text
1 总则    1
2 基本规定    3
	2.1 术语    4
	2.2 基本要求    5
3 技术要求    6
```

- 行尾数字是**目录逻辑页码**，不是 PDF 实际页序。
- 推荐每增加一级使用一个真实 Tab 缩进；上例子项以 Tab 缩进。
- 标题与页码之间用 Tab 或空格分隔。
- 空行及以 `#` 开头的注释行会被忽略。

### 命令行输出

以 `文档.pdf` 为例，默认路径为：

| 结果 | 默认文件名 |
| --- | --- |
| 全文 OCR 中间结果 | `文档_searchable.pdf` |
| 不经过全文 OCR 的书签结果 | `文档_bookmark.pdf` |
| 经过全文 OCR 后的书签结果 | `文档_searchable_bookmark.pdf` |
| 导出的目录校对文本 | 当前处理文件名加 `_toc.txt` |

向导允许自定义书签 PDF 和目录文本的输出路径。桌面版与命令行的文件命名不同；命令行已有同名输出可能被替换，运行前请检查目标路径。

## 配置

### 本地 OCR

项目中的 `config.json` 默认设置为：

```json
{
  "general": {
    "dpi": 200,
    "max_ocr_workers": 4
  },
  "ai_toc": {
    "enabled": false,
    "base_url": "https://api.openai.com/v1",
    "api_key": "",
    "model": "gpt-4o-mini"
  }
}
```

| 配置项 | 说明 |
| --- | --- |
| `general.dpi` | OCR 渲染分辨率，默认 200，配置加载时限制在 96–600；提高分辨率会增加计算和内存开销 |
| `general.max_ocr_workers` | 默认 OCR 并发进程数，可在界面或向导中调整；不是线程数，也不代表越高越快 |

程序按以下顺序查找，使用第一个存在的配置文件：

1. 环境变量 `PDF_ENHANCE_CONFIG` 指定的路径。
2. 当前工作目录的 `config.json`。
3. 项目目录的 `config.json`。
4. `~/.config/pdf-enhance/config.json`。

### 视觉 AI（可选，仅命令行）

需要支持**图片输入**的 OpenAI 兼容接口。将 `ai_toc.enabled` 设为 `true`，并填写实际服务的 `base_url`、`api_key` 和 `model`。

也可通过 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 环境变量覆盖对应字段；环境变量不会自动开启 AI，仍需设置 `enabled: true`。建议通过环境变量提供密钥，不要将真实密钥提交到仓库。

启用后，程序将选定的目录页渲染为图片并发送到该服务，可能产生 API 费用。敏感文档应先确认服务的数据处理政策。未启用 AI 时使用本地解析；AI 未返回有效目录时回退到本地解析。

## 限制与常见问题

### 自动找不到目录，或书签没有生成

- 自动目录探测目前限于 PDF 的**前 35 页**，且依赖版式与文字识别结果。目录在更后面时，使用命令行手动指定页码。
- 桌面版无法可靠确认页码偏移时会停止生成书签，不直接采用猜测偏移；可改用命令行检查目录和手动调整偏移。
- 已确认目标页但标题坐标匹配失败时，书签可能退回该页页首，完成消息会说明数量。
- 多页目录、节选文档及复杂版式需要抽查结果；某份文档识别成功不代表所有文档都能成功。

### PDF 已有文字，为什么仍可能需要 OCR？

有文字层不等于文字正确。乱码、控制字符和错误的字符映射可能导致搜索失败或高亮错位。程序会检查文字层质量；对于质量较差的扫描件，可选择重新 OCR。

### OCR 太慢或占用内存过高

先降低并发进程数，必要时降低 `dpi`。处理耗时与页数、分辨率、版面和机器性能有关，项目不承诺固定提速倍数。OCR 子进程失败时会报告失败页并停止生成。

### 原始文件会被修改吗？

程序禁止将输出路径设为输入文件本身。PDF 输出先写入临时文件，再替换目标文件，避免处理中断留下不完整输出。桌面版覆盖已有输出前会弹窗确认；命令行请自行检查同名输出。

### 加密 PDF 或 Windows 安全提示

桌面版遇到需要密码的 PDF 会要求先解密，请仅处理你有权访问的文件。未签名的 Windows exe 可能触发 SmartScreen；请确认下载来源，不要对来源不明的程序绕过安全检查。

## 开发与 Windows 构建

### 运行测试

在项目目录中，使用开发虚拟环境安装测试依赖：

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
```

### 构建桌面版

在 Windows 上安装 Python 3.12（含 `py` 启动器），进入项目目录运行：

```bat
build_windows.bat
```

脚本联网安装依赖、运行测试，并用 PyInstaller 打包 OCR 模型和 ONNX Runtime 依赖，生成：

```text
dist/
├── PDF-Enhance.exe
└── PDF-Enhance-Windows.zip
```

脚本会使用或创建项目内的 `.venv`，重新运行会覆盖同名构建产物。[Windows 构建工作流](.github/workflows/windows-build.yml) 也会上传这两个文件，但不会自动发布 Release。

发布前，应在干净的 Windows 机器上分别验证单文件版和便携版，检查中文 PDF、全文 OCR、书签跳转和高 DPI 显示。自动化测试与打包成功不能代替发行版验收。

### 项目结构

```text
pdf_enhance.py         # 命令行入口
pdf_enhance_gui.py     # 桌面界面
pdf_enhance_core/      # OCR、文字层、目录解析、页码偏移与书签模块
config.json           # 默认配置
build_windows.bat     # Windows 测试与打包脚本
tests/                # 自动化测试
```
